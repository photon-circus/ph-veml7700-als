# Code of conduct

## Expected behavior

Participants are expected to be respectful, technically honest, and
constructive. Disagreement about engineering is welcome and useful; the standard
is that it stays about the work.

Technical honesty carries specific weight in this repository. Evidence
provenance is the thing this project is built to protect, so the following are
conduct problems, not merely review problems:

- describing model, mock, or simulated results as hardware evidence;
- presenting a skipped or partial check as a passed one; and
- pressure to bypass a review gate because a change is small, urgent, or
  already written.

## Unacceptable behavior

Harassment, intimidation, personal attacks, sustained disruption, unwelcome
attention, publishing others' private information, and deliberate
misrepresentation of test evidence are not acceptable.

## Scope

This applies in every space the project uses — issues, pull requests, code
review, commit messages, discussions, and any private correspondence arising
from participation here. It also applies when a participant is representing the
project elsewhere.

## Reporting

Report privately to **steve@giacomelli.ca**. Include what happened, where, when,
and any links or screenshots that help. If you are unsure whether something
qualifies, report it anyway and say you are unsure.

Reports are handled confidentially. Your identity is not shared with the person
reported, or with anyone else, without your agreement — unless there is a safety
risk that makes disclosure necessary, in which case you will be told first.

You may report conduct you witnessed rather than experienced.

**No response-time commitment is offered.** This is a single-maintainer project.

## Enforcement

The maintainer reviews the report, gathers context, and gives the person
reported an opportunity to respond, unless doing so would create a safety risk.
Responses are proportionate and may include:

1. a private request to change specific behavior;
2. a private warning naming the consequence of continuing;
3. editing, hiding, or removing contributions that violate this policy;
4. temporary restriction from participation; or
5. permanent restriction from participation.

The reporter is told the outcome to the extent that doing so does not breach
anyone else's confidentiality.

## Conflicts of interest and appeal

The maintainer is currently the sole enforcer and is also the most active
contributor. That is a real limitation of a single-maintainer project, and it is
recorded here rather than glossed over.

If your report concerns the maintainer, or you believe an outcome was unfair,
you may escalate to GitHub Support, which can act on abuse independently of this
repository: <https://support.github.com/contact/report-abuse>.

If this project gains additional maintainers, this section will name an enforcer
who is not the subject of the report.
